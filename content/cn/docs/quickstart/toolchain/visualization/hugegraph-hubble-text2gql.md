在 Text2GQL 中输入“查询最多 5 个人物顶点”这样的问题，Hubble 会根据当前图的 Schema 生成 Gremlin 或 Cypher。
你可以直接查看结果，也可以修改语句后再执行。使用前，先按 [Hubble 基础与单机](/cn/docs/quickstart/toolchain/hugegraph-hubble/)启动服务，
确认能手动查询目标图。

- [先查一次图](#first-query) 从输入问题到查看结果。
- [配置模型](#models) 选择内置模型，或填入自己的临时连接。
- [调整 Prompt](#prompt) 修改生成要求和示例，保存为共享模板。
{.cards}

## 先跑一次查询 {#first-query}

1. 打开【图查询 → GQL 图遍历】，确认顶部选中了要查询的图。
2. 选择【使用内置模型】。如果还没有共享模型，切换到【使用临时模型】，填写连接信息。
3. 在【自然语言】中输入问题。默认生成 Gremlin，点击语言按钮可以切换到 Cypher。
4. 点击【生成并查询】。右侧会逐步显示生成的语句，生成结束并通过只读检查后，下方显示查询结果。
5. 在图、表格和 JSON 之间切换，核对结果。需要调整时，直接修改右侧语句，再点击【执行查询】。
{.steps}

![自然语言、可编辑 Gremlin 与图结果](/cn/docs/images/hubble/text2gql.jpg)

> [!TIP]
> Text2GQL 只使用当前账号有权读取的 Schema。生成的语句只允许读图，修改后再次执行也会做只读检查。
> 如果模型用错了类型或属性名，可以对照【元数据配置】修改语句，或把要求写得更具体一些。

按 <kbd>Ctrl</kbd> / <kbd>Command</kbd> + <kbd>Enter</kbd> 可以执行当前输入框的操作。
焦点在左侧时生成并查询，焦点在右侧时执行已有语句。
拖动输入框下方的分隔条，可以同时改变两个输入框的高度；图下方的分隔条用来调整图的高度。

## 选择模型 {#models}

| 入口 | 什么时候用 | Key 放在哪里 |
| --- | --- | --- |
| 使用内置模型 | 管理员已经配置好模型，直接提问即可 | 加密保存在服务端 H2 中，不会回传浏览器 |
| 使用临时模型 | 想用自己的模型地址、模型名称和 Key | 只留在当前页面内存，刷新或切换账号后清除 |

切换到【使用临时模型】时，配置行会自动展开，也可以手动收起。
填写【临时 API 类别】、Base URL 和模型名称，需要 Key 的服务再填写【临时 API Key】。
OpenAI、DeepSeek、GLM 等服务选择【OpenAI 兼容接口】，本地 Ollama 选择【Ollama（本地）】。
模型名称要填该服务实际提供的模型 ID，本地没有启用认证的 Ollama 可以不填 Key。

Base URL 要能从 **Hubble 后端所在主机**访问。Hubble 在容器里运行时，`localhost` 指容器自身。
公有模型服务使用 HTTPS，本地或私网模型可以使用 HTTP。Key 填在单独的输入框中，不要写进地址。

> [!DETAILS]- 浏览器会记住哪些配置
>
> 临时接入方式、地址和模型名按账号放在 `sessionStorage` 中，在本次浏览器会话里保留。
> 成功用过的 Base URL 和模型名还会进入同账号的 `localStorage` 最近记录，下次可以从输入框下拉选择。
> 这些浏览器记录都不保存 Key。

### 设置共享模型

管理员可以在【系统与运维 → 模型设置】配置共享模型，普通账号直接使用已保存的配置。
Server 没有开启认证时，能够访问该部署的用户都可以修改模型设置。

填写接入方式、Base URL、模型名称和 Key，启用后点击【保存并测试】。
Hubble 会先保存，再发一条不带图数据的简短请求，确认模型能否回复。
如果显示保存成功、测试失败，配置已经保存，可以按错误提示修改后重试。

【测试已保存配置】只测试服务端已经保存的值。改过表单后，要先保存或放弃修改，再使用这个按钮。
已保存的 Key 不会显示出来，留空会保留原值。更换模型地址时需要提供新 Key，本地无需 Key 的 Ollama 除外。

![模型设置及标题旁的 Prompt 入口](/cn/docs/images/hubble/text2gql-settings.jpg)

> [!DETAILS]- 共享 Key 的保存与备份
>
> 共享配置和 Prompt 保存在 Hubble 的 H2 元数据库中。Key 加密后保存，默认主密钥文件是 `data/text2gql-master.key`。
> 备份 H2 时，还要单独保留这个文件，丢失后就无法解密原来的 Key。文件只允许属主读取，并应随 Hubble 数据卷跨重启保留。
> 也可以通过 `HUBBLE_TEXT2GQL_MASTER_KEY` 提供 Base64 编码的 32 字节密钥。

## 调整 Text2GQL Prompt {#prompt}

如果想固定查询习惯，或补充几个生成示例，在【模型设置】标题旁打开 **Text2GQL Prompt**。
Gremlin 和 Cypher 各有一份模板。当前图的 Schema 会自动附加，问题会单独发送，不用把 Schema 手动复制进模板。

1. 选择语言，修改生成要求或 few-shot 示例。示例中的类型、属性和关系名称，要能在实际图里找到。
2. 点击【应用】，将改动带回模型设置表单。
3. 保存模型设置。之后的生成请求才会用上这份新模板，刷新页面后也会保留。
{.steps}

![带 few-shot 示例的大尺寸 Prompt 编辑器](/cn/docs/images/hubble/text2gql-prompt.jpg)

【取消】会放弃编辑框里的本次改动。【恢复内置默认】只恢复当前语言的草稿，仍需应用并保存。
内置模型和临时模型都使用这套共享模板。查询页不需要另外设置 Prompt，修改模板也不会关闭服务端的只读检查。

## 异步提交与执行记录

使用 AI 时也可以异步执行。把右侧模式切到【异步】，左侧按钮会变成【生成并提交】，右侧则是【提交任务】。
提交后点击【查看任务进度】，到任务页面确认最后的结果。任务被接受后仍可能执行失败，要以任务页面的最终状态为准。
异步执行需要 Server 提供对应语言的任务接口，使用 Cypher 时也要确认这一点。

左侧底部显示模型生成耗时，其中包含必要的语句修正时间，不包含准备 Schema 的时间。
右侧显示一次查询请求的往返耗时，不包含模型生成或图渲染。异步记录中的提交耗时，也不包含后台任务后续运行的时间。
生成并自动查询时，遇到无效输出或能识别的语法、Schema 错误，最多再修正一次。
网络、认证或异步提交失败时，不会重新生成语句。

再次打开同一张图，输入框会按语言恢复最后一次记录的问题和语句，同步查询和异步提交都算。
恢复记录不会自动执行；如果已经开始编辑，迟到的记录也不会覆盖输入。切换 Gremlin 和 Cypher 时，两边各自保留草稿。

执行记录里的【自然语言】列可以帮你找回当时问了什么，手写查询没有问题文本时显示 `—`。
记录和收藏会在图下方完整展开，直接向下滚动浏览器就能查看当前页和分页按钮。

生成请求会把问题、当前 Schema 和必要的纠错信息发给所选模型服务，查询结果不会发送。
Hubble 会保存问题和执行语句供以后查看，临时 Key 不会写入执行记录或 H2。

## 遇到问题时

| 遇到的情况 | 可以先检查什么 |
| --- | --- |
| 内置模型不可用 | 由有权限的用户检查模型设置，确认已启用，地址和模型名填写正确 |
| 本地模型连不上 | 从 Hubble 后端检查 Base URL，容器里的 `localhost` 不指宿主机 |
| 应用 Prompt 后刷新，改动不见了 | 应用只改了表单，还需要保存模型设置 |
| 生成的语句被拒绝或查不出来 | 对照当前 Schema 检查名称，再看只读限制和 Server 支持的查询语法 |
| 异步提交失败 | 检查任务接口和当前账号权限，先用即时查询核对语句能否执行 |
